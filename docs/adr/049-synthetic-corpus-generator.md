## Context

ADR-048 landed the memory-truth schema (migrations `0020`/`0021`): every table exists, every CHECK enforces 06's taxonomy, and every table is empty. 18 §4 puts the synthetic corpus generator next — "first" among behavioral components, before the gate — because 07 Part XVI calls it "the single most valuable test asset in the project" and every later performance, migration, and integrity suite is defined against it. Confirmed against the real repository on 2026-09-18: `tools/` has no generator; `tests/fixtures/` has no corpus package; CI (`.github/workflows/ci.yml`) has exactly two jobs, commit-tier (`tests/unit tests/suites`) and merge-tier (`tests/integration`), no scheduled run, and `pyproject.toml` registers no pytest markers; no `Rng` port exists under `domain/ports/` (11 §14 names one; nothing in `src/` needs randomness yet); `kernel/runtime/ids.py::uuid7` takes an injectable byte source, so ids can be seeded without touching production code.

Four things 07/13/17/18 leave open, found while grounding this:

**Finding 1 — 17 §2 names two homes, and one of them is structurally impossible.** The tree comment under `tools/` reads "dev-only: linters/contracts, corpus generator, docs builder"; the comment under `tests/fixtures/` reads "scenario scripts, fixture vaults, synthetic corpus." §4.2's `tools` row: "❌ src imports at runtime; MAY parse/inspect the tree as text." A generator has to *build a database at the current schema*, which means calling `adapters/sqlite/migrations.py::apply_migrations` — a `src/` import. Re-implementing the migration harness inside `tools/` to avoid the import would be a second schema authority (AR6). The generator can only live in `tests/fixtures/`. This is Option 1.

**Finding 2 — 18 §4's "corpus first, then gate" and E3's "ports before implementations" pull in opposite directions.** A generator that writes through store ports needs those ports to exist first — and the ports' real consumers (the gate, the lifecycle function, retrieval) are the later slices whose needs should shape them. A generator that writes raw SQL needs no port and matches 18's order literally, but is a bulk writer that bypasses store-layer invariants (there are none yet: the schema *is* the invariant at this point). Option 2.

**Finding 3 — determinism needs a seeded source, and the constitution names a port for it that nothing in `src/` uses.** 11 §14: "Randomness likewise (`Rng` port) — needed for jitter, seeded in tests." No jitter code exists (AG §10's retry backoff is RESERVED, 03 §8). A port whose only consumer is a test fixture is a port with no real implementation to contract-test against. Option 3.

**Finding 4 — the corpus's consumers are nightly-shaped, and no nightly tier exists.** 13 §3's table says "Nightly: performance budgets on 10-yr corpus"; 03 §3 lists "nightly CI tier" as Phase 2 required infrastructure. A 10-year corpus is on the order of a million rows (06 §13.1) — minutes to generate, wrong for the commit tier. Landing the corpus without the tier that runs its expensive suites produces tests that pass by never running. D5.

**What is settled and not re-decided here:** the scale bands (06 §13.1), the budgets (07 Part XIV, 06 §13.2), the suite taxonomy and directory names (13 §2, 17 §11), the schema (ADR-048), the rule that no `.db` file is ever committed (PS-002), and the rule that nothing from Kang's vault enters the repository (14 §14.5) — the corpus's text is generated from fixed word lists, never from his notes.

## Options

### Option 1 — Where the generator lives

**1A — `tools/corpus_generator.py`, per 17 §2's `tools/` comment.** *For:* the comment says so. *Against:* structurally impossible without re-implementing the migration harness (Finding 1); a `tools/` script is not under any test suite, so its SQL drifts from the schema silently. Rejected on structure, not taste.

**1B — A fixture package, `tests/fixtures/corpus/`. (Recommended.)** *For:* `tests/` may import everything (17 §4.2), so the generator builds its database through the real harness — exactly the code `Core`'s own startup runs; the package is under the suite that consumes it; `python -m tests.fixtures.corpus year5 out.db` gives a human the same artifact for hands-on inspection without a second code path. *Against:* 17 §2's `tools/` line needs a dated correction — one comment, not a decision reversal, since the same document already names `tests/fixtures/` for the corpus.

### Option 2 — How the generator writes rows

**2A — Through new insert-only store ports (`MemoryStore.insert_many`, `EpisodeStore`, `LinkStore`, `VaultIndexStore`, `CandidateQueueStore`) with fakes and SQLite adapters landing in this slice.** *For:* E3/11 §5 ("ports before implementations"); the corpus exercises the real write path; ADR-048's owed claim (no port carries the integer rowid) becomes provable now. *Against:* five ports designed against a test asset, before their real consumers exist — the gate will need `insert` to be the *approval* step with its audit and event pairing, the lifecycle function will need `transition`, retrieval will need prefiltered reads; shaping the port surface from a bulk-load use case first is designing for the wrong caller, and every one of those slices would then reshape what this one froze. It also triples the slice (five contract suites) and puts `src/` code into a slice 18 §5 describes as "tests/fixtures has no inbound edges."

**2B — Raw, parameterized SQL inside the fixture package, explicit column lists, chunked into ≤1000-row transactions. (Recommended.)** *For:* matches 18's literal order (corpus, *then* gate); the sanctioned precedent already exists at scale (`test_memory_schema.py`); no `src/` code, so the slice is deletable by removing one directory; DB-002's own bulk-write rule is followed verbatim; the schema suite plus this generator's own tests are the drift guard (a column rename breaks generation loudly). *Against:* the corpus never goes through store invariants — acceptable exactly because none exist yet, and *by design* permanent: the corpus is a schema-level asset that fills tables, not a simulation of the gate (the gate's own suite proves the gate; the corpus proves scale). ADR-048's owed rowid claim stays owed to the gate slice, where the first port appears. Named, not hidden.

### Option 3 — The determinism source

**3A — A new `Rng` port in `domain/ports/` with `FakeRng`, used by the generator.** *For:* 11 §14 names it. *Against:* its only consumer would be a test fixture; the "real" adapter (`os.urandom`/`random.SystemRandom`) would have no `src/` caller; a port with one fake and no production consumer is the smell CLAUDE.md §10 names ("a port with exactly one conceivable implementation and no fake" — inverted here, but the same emptiness).

**3B — `random.Random(seed)` from the standard library, inside the fixture package; `uuid7`'s byte source fed from it; the injected `FakeClock` for every timestamp. No port. (Recommended.)** *For:* deterministic by construction, zero new surface; the `Rng` port arrives with its first `src/` consumer (retry jitter), exactly as every other port in this codebase arrived with a real caller. *Against:* when the port does arrive, the generator is not obliged to adopt it — fine: the generator is a fixture, not domain code, and 11 §14's ban is on `src/`.

## Decision

### D1 — Home and shape: `tests/fixtures/corpus/`, a package with a `__main__`

Modules: `profiles.py` (the three profiles as frozen dataclasses of per-table target counts and distribution weights, each number citing its 06 §13.1 band or its 06/07 source), `text.py` (synthetic sentence and note generation from fixed word lists shipped in the package — never read from any file outside the repo), `generate.py` (the writer: opens a fresh database via `open_connection`, applies the shipped migrations via `apply_migrations`, fills tables in FK order in ≤1000-row transactions), `__main__.py` (`python -m tests.fixtures.corpus <profile> <out.db> [--seed N] [--fraction F]`). A session-scoped pytest fixture in `tests/fixtures/corpus/__init__.py` (or the package's conftest — the builder decides which; both are inside `tests/`) yields a generated database path per profile under `tmp_path_factory`; nothing is ever written under the repository (PS-002; tree hygiene lint already bans `.db`). 17 §2's `tools/` comment gets a dated correction; no `tools/` wrapper is added.

### D2 — Writing: raw SQL, explicit columns, FK order, chunked (Option 2B)

Tables filled, in dependency order: `goal`, `project`, `competition`, `milestone`, `task`, `deadline` (the structured store — real entity ids for `about_*` links and P0 views); `conversation`/`message` (a small population, so `fts_message` has content); `vault_note`, `vault_chunk`; `memory_record`, `memory_revision`, `memory_candidate_queue`; `episode`; `link`; `link_index` (written directly with `origin` ∈ `link`/`fk`, mirroring what the indexer will derive — the corpus is honest that it *simulates* the derived state); a handful of `tombstone` rows. `change_log` fills itself through the capture triggers (a realistic side effect, counted in the size estimate, not suppressed). Not touched: `embedding_version` (empty), every `embedding_ver` (NULL), `vec_*` (do not exist), the event log, audit files — the corpus is a `kang.db` asset only. `sensitivity='private'` rows carry `content='[encrypted]'` and random bytes in `content_enc` — stated plainly as fake ciphertext, since DB-005's mechanism is a later slice; their exclusion from `fts_memory` is thereby exercised at scale. Every provenance column is populated with a synthetic but shape-correct value (`source_kind` from 07's enum, `source_detail` matching its kind's format, `reason` non-empty, `created_by` a principal-shaped string).

### D3 — Profiles: `year1`, `year5`, `year10`, at the midpoints of 06 §13.1, with a `fraction` scale

| Profile | `memory_record` | `episode` | `vault_chunk` | `link` | Tier it runs in |
|---|---|---|---|---|---|
| `year1` | 3,500 | 4,500 | 35,000 | 20,000 | merge (integration) |
| `year5` | 22,000 | 22,000 | 175,000 | 140,000 | nightly |
| `year10` | 45,000 | 45,000 | 350,000 | 275,000 | nightly |

Structured-store, queue, revision, and note counts are derived from these by fixed ratios in `profiles.py` (each with its one-line reason). `fraction` (default 1.0) scales every count for fast local runs; the determinism contract holds per `(profile, seed, fraction)`. Distributions are starting hypotheses in the sense 06 Appendix A uses the phrase — types weighted so `fact`/`observation` dominate and `rule`/`profile` are rare; statuses mostly `active` with `under_review`/`superseded`/`archived` minorities; `superseded` records carry a matching `supersedes`/`superseded_by` link pair; `lesson` records carry `derived_from` links to episodes; episodes follow their cadence (`plan` daily, `review` weekly, `retrospective` per completed project). The generator's own test asserts each table's count lands inside its 06 §13.1 band at `fraction=1.0`.

### D4 — Determinism: `(profile, seed, fraction)` ⇒ identical row content; a pinned golden for `year1`

Two generations with the same inputs must produce identical content: proven by a per-table digest over rows selected in `id` order (never the file bytes — SQLite file bytes are not a contract). The `year1` digest is additionally pinned as a golden (13 §2.17): any change to the generator's distributions or vocabulary changes the golden, and that diff is reviewed like code. Timestamps come from an injected `FakeClock` advanced deterministically; ids from `uuid7` fed by the seeded `Random`; `device_id` is one fixed synthetic value per profile with a small second-device minority (the sync quartet is exercised, not faked uniform).

### D5 — The first consumers land with the corpus: migration-on-corpus and the measurable budgets, and the nightly tier that runs them

- `tests/suites/migration/` (13 §2.11; the directory is 17 §11's own reservation) — the full chain applies on a *populated* `year1` database (merge tier) and `year10` (nightly); after apply: `PRAGMA integrity_check` = `ok`, `PRAGMA foreign_key_check` empty, every FTS table passes `'integrity-check'`. Honest scope: the "N-1→N on the corpus" claim is met going forward — the corpus targets HEAD; a future schema-changing migration's own test seeds pre-shape rows by hand (the `0006`/`0020`/`0021` pattern) and the corpus proves the chain still applies at scale.
- `tests/suites/performance/` (13 §2.12) — only the budgets measurable *today*, each a constant citing its 07 Part XIV line, on `year10`, `nightly`-marked: FTS deep query < 100 ms; the Part VII recursive link query at depth 2 < 10 ms; `VACUUM INTO` snapshot < 60 s; the two real P0 read shapes (`TaskStore.plannable()`, `DeadlineStore.active()`) < 20 ms; open + PRAGMA + version check < 500 ms. Not measurable yet, named: hybrid candidate fetch (needs `vec_*`), full index rebuild (no rebuild command), single-row insert via the write queue (no memory store). `config/defaults/performance.toml` (07 Part XVIII's "CI budget mirror") stays unbuilt: tests may not read repository `config/` (17 §8), and its runtime reader (the health panel's budget×1.5 alert, Part XVII) is a later slice — the constants live in the suite with citations until then.
- The `nightly` marker is registered in `pyproject.toml` (a `strict-markers` posture so a typo cannot silently un-mark a test), commit/merge jobs deselect it, and `ci.yml` gains a scheduled job that runs it. This is 03 §3's "nightly CI tier" as required Phase 2 infrastructure — its first, smallest form.

### D6 — What this slice does not do

No `src/` code of any kind: no port, store, fake, `Rng` port, or config file. No `.db` artifact in the repository. No vectors, no `embedding_version` row. No use of the corpus by the memory-integrity suite (13 §2.8 — needs the gate). No modelling of the gate's behavior: rows are placed in the states 06 allows, not driven through transitions.

## Consequences

**Easier:** every later Phase 2 slice can prove its budget on decade-scale data from its first commit; migration tests stop running only on empty databases; the nightly tier exists to be extended (replay scenario, memory integrity full — 13 §3) instead of being invented later under pressure; the ADR-048 rowid claim gets its proof target (the gate's first port) without this slice pre-shaping that port.

**Harder, or a cost:** a large fixture package under the size lints' spirit even where the lint's scan does not reach (`lint_sizes.py` scans `src/`; the builder keeps fixture modules under the same limits anyway — a 1,500-line generator is the same maintenance debt in any directory). Nightly runs have no history to compare against, so 13 §2.12's *slope* tracking starts empty. The `year1` golden digest will change whenever the generator's vocabulary or weights are tuned — deliberately, and each such change is a reviewed diff. Generation time for `year10` (minutes) is paid nightly, never on commit. The corpus is permanently a schema-level asset: it will never exercise store-layer invariants, and no test may claim it does.

**Named, not decided here:** the `Rng` port (arrives with retry jitter); pseudo-vectors for `vec_*` (the embeddings slice extends `profiles.py`/`generate.py` when the tables exist); a fixture *vault directory* for the Obsidian slice (a different asset: real Markdown files for the indexer to read — the corpus's `vault_note`/`vault_chunk` rows simulate the indexer's output, not its input); `performance.toml` and the health panel's budget alerts.

## Verification

**Not yet implemented.** What would prove this ADR: the generator's own tests (two generations with one seed produce identical per-table digests; a different seed produces different ones; `year1` matches its pinned golden; every table count sits inside its 06 §13.1 band at `fraction=1.0`; `integrity_check`/`foreign_key_check`/FTS `'integrity-check'` clean after generation; every `private` row is absent from `fts_memory`; `superseded` records each have their link pair; zero `embedding_ver` set; nothing written outside `tmp_path`); the migration-on-corpus suite; the performance suite green on `year10` with each measured number recorded in the commit; the nightly job visibly present in `ci.yml` and the marker registered; the whole existing suite unchanged in count except for the new items.
